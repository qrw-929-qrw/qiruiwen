答辩追问 ①：第一版提示词漏掉了哪个需求？（点击展开）

Q：你的第一版提示词漏掉了哪个需求？

A：四个需求都"提了"，但只给了方向、没给验收标准：没写 3200ms 这个数值，没说"拖动后自动播放要继续"（disableOnInteraction: false），没说圆点要可点（clickable），也没指定分页器的具体元素 id 和动画时长。结果是 AI 只能按默认值猜。

Q：你是怎么在第二轮里"说清楚"的？

A：把模糊目标改写成可检查的约束——每条都写清 ① 配置项路径（如 autoplay.delay）② 具体取值 ③ 对应的页面元素 ④ 期望看到的现象；再追加"只输出代码"，避免解释文字里夹带错误信息。

Q：AI 第一次给的代码错在哪？

A：三处实质错误：autoplay 用数字简写导致拖动后停播；pagination 缺 clickable 导致圆点不可点；分页器选择器写类名而非 #wyPag4 会串台。另有两处"能用但不合要求"：延迟 3000≠3200、缺 speed: 800。

任务二 · creative 仿写：课堂没讲，AI 教我

先读官方示例 swiper/demo/257-effect-creative.html：它只写了 creativeEffect: { prev: { translate: [0,0,-400] }, next: { translate: ['100%',0,0] } }。读懂的结论是——creativeEffect 是一个"状态描述"对象，prev 描述已退到左边那张的终态，next 描述还在右边等着进来那张的初始态，中间过程由 Swiper 按 translate / rotate / scale / opacity 自动插值。

我的"电影投影"参数（本页演示四的第 7 个按钮）

creativeEffect: {
  limitProgress: 2,                    // 前后各堆叠一层"胶片"
  prev: {
    translate: ['-42%', 0, -400],      // 左退 42%，z 轴再远离观众 400px
    rotate: [0, 0, -10],               // 逆时针倾斜 10°
    scale: 0.72,                       // 缩小到 72%
    opacity: 0.38                      // 压暗，退到后景
  },
  next: {
    translate: ['112%', 0, 140],       // 停在右侧屏外、且比屏幕更靠近观众
    rotate: [0, 0, 9],                 // 顺时针倾斜 9°
    scale: 1.18,                       // 放大到 118%
    opacity: 0.3                       // 半透明
  }
}

上一张缩成小片、歪在左后方并压暗，像放映机后面垂着的旧胶片；下一张比正看着的那幅更大，从右侧斜着扑进来再落回正常尺寸，形成"投影打过来"的压迫感。

答辩追问 ②：prev / next 的 transform 各控制什么？（点击展开）

prev —— 控制"刚被翻过去、退到左侧的那一张"的终态

translate: ['-42%', 0, -400] 让她 x 轴左移 42%、z 轴后退 400px（后退＝视觉变小变远）；rotate: [0,0,-10] 在屏幕平面内逆时针歪 10°；scale: 0.72 再缩小到 72%；opacity: 0.38 压暗，制造景深。

next —— 控制"还在右侧、尚未进场那一张"的初始态

translate: ['112%', 0, 140] 停在容器右侧之外，z 轴朝观众方向前进 140px；scale: 1.18 比当前图更大（这就是"放大"的来源）；rotate: [0,0,9] 带一点角度；opacity: 0.3 半透明。切换时从该状态插值回"居中、scale 1、opacity 1"，看起来就是放大右移着滑进来。

Q：transform 里的百分号是相对谁？

A：相对轮播容器（.swiper）自身尺寸，不是相对图片——translate 的 x 用容器宽度的百分比、y 用容器高度的百分比。所以容器改成响应式宽度时参数不用重算。

Q：改一个数值让下一张转 20 度？

A：改 next.rotate 的第三个数 → rotate: [0, 0, 20]。三个数分别绕 X / Y / Z 轴：X 轴上下翻转、Y 轴左右翻牌、Z 轴才是屏幕平面内打转。

加分能力：键盘控制（keyboard）

keyboard: { enabled: true, onlyInViewport: true }

enabled: true 开启键盘控制，按 ← / → 切换；onlyInViewport: true 只在轮播进入视口时生效——本页有 4 个轮播，少了这一项会出现"按一次键 4 个轮播一起翻"。

答辩追问 ③：这段代码什么意思？AI 第一次给的不对在哪？（点击展开）

Q：这段代码什么意思？

A：keyboard 是 Swiper 的键盘模块配置。enabled 打开键盘控制，左右方向键触发上/下一张；onlyInViewport 用可见性判断决定是否响应按键，避免多轮播页面同时被驱动。

Q：AI 第一次给的不对在哪？

A：它给的是 keyboard: true（Swiper 5 时代的布尔写法）。Swiper 8 之后该参数只接受对象，布尔值会被忽略——表现就是"写了但按键没反应"；而且没加 onlyInViewport，4 个轮播会同时响应同一个按键。

Q：新增的作用？

A：一是可访问性——不用鼠标也能翻页；二是体验——看大图时手不用在鼠标和方向键之间来回切换。
